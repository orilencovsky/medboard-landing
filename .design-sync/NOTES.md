# design-sync notes — medboard-landing / MeduXa Landing DS

## What this sync actually is

`medboard-landing` is a plain static HTML site (`index.html` (Hebrew root) + `en/index.html`, no framework, no build, no `package.json` at repo root) — there was **no real component library to extract**. With the user's explicit sign-off, a synthetic library (`design-system/`) was authored from scratch by hand-carving the landing page's markup into React components (`design-system/src/*.tsx`), so this Claude Design project could be seeded. This is fabrication, not extraction — unlike a normal design-sync target, there's no upstream source of truth to re-sync against; `design-system/` **is** the source of truth going forward.

15 components now (14 original + `FeaturesLoop`, added 2026-09-02 — see the Features-loop entry below).

Target project: **"MeduXa Landing"**, `projectId` in `.design-sync/config.json` — separate from the existing "MeduXa Design System" project (that one syncs the actual app, `/Users/ori/Desktop/Pilot`).

Re-checked again after the `feat/features-loop` merge and the `fb763b4` geometry fix: pulled `NODE_POSITIONS` and the ring `<path d>` values straight from the rendered DOM and diffed them against `en/index.html`'s loop section directly — byte-for-byte match. ## Re-sync risks

- **Features is now `FeaturesLoop`.** The landing page's Features section was rebuilt as a four-step ring (Practice → Understand → Review & Retain → Compete) on `feat/features-loop`, hand-ported into `FeaturesLoop.tsx` / the `.ds-loop-*` block in `styles.css` while that branch was still unmerged (read via `git show`, matching this DS's LTR-only/English-copy convention). `feat/features-loop` was then merged into this branch (2026-09-02) — `index.html`/`en/index.html` now carry the loop directly, so the DS and the live markup agree again. **Caught mid-merge**: `feat/features-loop` had picked up a same-day follow-up (`fb763b4`, "Run the English ring clockwise") flipping the English ring's SVG sweep direction and swapping step 02/04's ring position, *after* the initial port — `FeaturesLoop.tsx` was updated to match and re-verified against the merged `en/index.html` byte-for-byte (`NODE_POSITIONS` and the three arc `d` attributes). This is exactly the "hand-port must be kept in sync" risk the next bullet describes, catching itself before merge — re-diff `FeaturesLoop.tsx` against `en/index.html`'s loop section on the next sync regardless, don't assume this note caught everything since.
- **`FeatureCard` is unused by the live page** (Features is `FeaturesLoop` now) but was kept, not dropped — its shape (small `--ds-bg-app`-tinted card, inline gradient dot) is distinct from the white chip-layout cards (`StepCard`, `PrincipleCard`), so it's a real, non-redundant primitive other grids may still want. Its doc comment now says so explicitly instead of claiming the Features grid.
- **Two new tokens**: `--ds-violet-onDark` (`#A78BFA`) and `--ds-violet-onDark-soft` (`#C4B5FD`), added to the existing violet block in `styles.css` without touching the ramp. `--ds-violet-light` (`#7C5CFF`) is only 3.5:1 on `--ds-navy-card` (`#0B2545`) — short of AA for the loop's violet-track text/icons on that panel — these two clear it (5.7:1+). Same rationale and values as the shipped page's own hardcoded `#A78BFA`/`#C4B5FD` in `ee46e7f`.
- **The two are not wired together.** If `index.html` / `en/index.html` change, `design-system/src/*.tsx` does NOT update automatically — there's no build step reading the HTML. Any future landing-page edit that should be reflected in the DS must be hand-ported into the matching component.
- **`DemoCard` is behind the shipped hero card.** The landing page's question card became interactive (per-answer tutor lines, an expandable KDIGO panel, and a one-message chat against `/api/tutor`); `DemoCard.tsx` still models only the original static shape — question, options, one tutor tip, progress bar. Its props API is still accurate for what it does render, so nothing is *wrong* in it, but a design built from this DS will not show the chat or the staging panel. Porting them is new work, not a gap-fill.
- **RTL (the Hebrew root `index.html`) was not modeled.** All 15 components, `FeaturesLoop` included, are LTR-only, matching `en/index.html`. The Hebrew page mirrors the same design but was not given a `dir` prop or RTL variant — if the design agent needs to build RTL screens with this DS, that's new work, not a gap-fill. **The loop specifically is no longer just a translation**: since `fb763b4`, Hebrew and English run the ring in mirrored directions on purpose (English clockwise for LTR reading; Hebrew kept its original geometry, which reads correctly for RTL) — step 02/04 sit on opposite sides between the two pages, and the SVG arcs sweep opposite ways. An RTL variant of `FeaturesLoop` would need to reproduce that mirroring, not just flip `dir` and reuse English's coordinates.
- **Copy is illustrative, not exhaustive.** Multi-item sections (9 Science principles, 4 How-it-works steps) are modeled as a single reusable card component (`PrincipleCard`, `StepCard`) with 2-3 sample instances in the authored preview — not all 9/4 real copy blocks. `FeatureCard`'s old "7 Features" grid no longer exists on the page (see above); `FeaturesLoop`'s 4 steps, by contrast, are modeled in full — all real shipped copy, not samples, since the loop is exactly 4 fixed steps rather than an open-ended grid. The full copy lives in `index.html` / `en/index.html` if ever needed verbatim.
- **Fonts load remotely.** IBM Plex Sans/Mono ship via a Google Fonts `@import` in `styles.css` (matching production, which loads the same family via a `<link>` in `<head>`) — not bundled locally. Any design built with this DS depends on that CDN being reachable.
- **`design-system/` toolchain**: Node v24, tsup 8.x, TypeScript 5.x — no monorepo, no workspace quirks. `npm run build` from `design-system/` is the only step before re-running the converter.
- **`.ds-sync/` is not committed** (regenerate by copying the skill's scripts again, `npm i esbuild ts-morph @types/react playwright` in it, `npx playwright install chromium`).
